# AOT v2 M11 设计

## 统一状态

`latcd` 为每个 source 保存已接收键 `known`。准备编译时读取当前清单所指模块的实际
TB 表，计算 `pending = known - module_tbs`。缓存为空或当前模块无效时，`pending`
就是完整 `known`。第一次编译和增量编译都处理同一种 pending 快照。编译期间到达的
键留给下一批，不修改正在编译的快照。

客户端提交二进制 `TBKeyBatch`。文件头包含 magic、版本、source SHA256、记录数和
提交序号；记录只包含 RVA 与语义 flag。协议只有 `SUBMIT_KEYS`、`FLUSH_SOURCE` 和
`FLUSH_ALL`，不解析旧版本。

## 发布和加载

第一次发布翻译完整键集合。后续发布只翻译 `pending`，把生成的 native image 合入
上次的完整 native image，再链接一个替换 `.so`。`current` 版本 2 清单只保存一个
`.so`、一个完整 `.native`、一个完整 `.tbset`、source、codegen ID 和发布序号；不解析
旧清单格式，也不保存增量模块数组。

如果 `pending` 为空但 `known` 比清单中的 TBSET 新，说明静态 CFG 已经把新增观察键
编入当前模块。此时只写入完整 TBSET 并原子替换清单；模块和 native image 保持不变，
不得启动翻译器或链接器。`flush` 仍要等这个清单发布完成后才能返回成功。

三个新文件写入临时目录并完成 `fsync()`，再移动到缓存目录。目录同步完成后，才用
临时文件、`fsync()`、`rename` 发布清单。清单是唯一生效点。编译、合并、链接或清单
发布前失败时，删除未生效的新文件，旧清单及其三个文件保持不变。清单生效后才删除
上一代文件。因此每次成功的 `FLUSH_SOURCE`/`FLUSH_ALL` 返回时，已接收的增量已经合并
并重新链接，下一次启动只加载一个模块。

运行时为清单中的唯一模块创建一个 guest ELF 实例，在已排序的 `(RVA, flags)` 表中
二分查找。串行请求可以使用更严格的 parallel-safe TB；parallel 请求不能使用串行
TB。

模块内可解析的 TB 目标保留直接跳转。增量 native image 与旧 image 出现相同 TB 时，
合并器保留旧 TB 表项；新增代码中的目标通过完整 TB 表解析。缺少模块内目标不得删除
发起跳转的 TB。

## 调度和合并

默认增量模式下，首个 pending 键立即排队。后台允许最多 100 ms 的批量合并窗口，
最老键等待不超过 500 ms；收到 flush 时立即编译。`--flush-only` 模式只接收并合并
键，不在应用运行期间启动编译；`FLUSH_ALL` 把此时全部 source 的最终并集各排队一次。
一个 source 同时只有一个编译任务，不同 source 由 worker 并行处理。默认 worker 数
取在线逻辑 CPU 数，最多 8 个。

没有分片数量参数。第一次和增量发布遵循同一规则：只翻译当前模块尚未包含的键，发布前生成
一个包含全部已发布 TB 的 native image 和一个替换模块。新清单发布前旧模块持续可用；
失败时保留旧清单并使对应 flush 返回失败。已经加载旧代码的进程保留旧映射到进程
结束。

## 收集开销

TB 创建时只把固定大小的键写入线程本地缓冲区，不增加执行计数。后台线程批量去重
和提交。缓冲区或持久化失败必须计入错误并在严格模式失败，不能静默丢弃。后台线程
每 100 ms 提交一次，所以守护进程或长时间不退出的进程也会持续更新集合。退出钩子
只提交尚未发送的缓冲区，不扫描完整 TB 哈希表。`execve`/`execveat` 前同步提交当前
进程待发送的键，避免 fork 子进程在 exec 前执行的文件代码丢失。

## 静态补全和严格验收

编译器从最终键集合开始，并补上确定可达的直接后继：条件分支两侧、直接调用的返回
地址和目标、间接调用/跳转后的顺序地址，以及系统调用后的顺序地址。含 parallel 键
的 ELF 还加入动态导出函数入口，用于覆盖动态链接器可能选择但本次收集未执行的入口。
这些规则在一次编译中处理，不靠重复运行或重复编译增加覆盖率。

`LATC_STRICT_FILE_AOT=1` 禁止所有文件映射代码进入 JIT，但允许 vDSO 等非文件代码；
它是 Python、Git、SQLite、Redis 的正式覆盖验收模式。`LATC_STRICT_AOT=1` 连非文件
代码也禁止，只用于更严格的诊断。覆盖率必须为 100%，且子进程在 exec 前不得生成
文件型 JIT TB。

TB 集合已排序去重。编译器一次分配 TB 数组，只检查编译前已有的模板；动态符号使用
哈希表判重，避免随 TB 数平方增长。最终干净构建在 3A6000 上处理约 10 万个运行时
TB、36 个 ELF，`FLUSH_ALL` 实测 7.703 秒，编译失败数为 0。
