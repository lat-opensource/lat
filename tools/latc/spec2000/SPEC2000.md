# SPECint2000 AOT validation

The validation uses the static x86-64 executables from
`specbin/x64_gcc12_2_0` and the official SPEC test workloads. A profile bundle
is run first with `LATC_PROFILE_OUT`; the resulting program addresses are fed
to `compile-aot.sh`. The final output is then run by `runspec` with strict AOT
checking enabled.

Validated on 2026-08-20 on LoongArch 3A6000:

| benchmark | final TBs | profile TBs | AOT bytes | program JIT | system JIT | SPEC test |
|---|---:|---:|---:|---:|---:|---|
| 164.gzip | 38,372 | 21 | 10,372,928 | 0 | 0 | PASS |
| 175.vpr | 49,645 | 32 | 13,455,200 | 0 | 0 | PASS |
| 176.gcc | 142,222 | 47 | 38,144,040 | 0 | 0 | PASS |
| 181.mcf | 42,239 | 24 | 11,383,904 | 0 | 0 | PASS |
| 186.crafty | 51,507 | 29 | 14,064,336 | 0 | 0 | PASS |
| 197.parser | 53,873 | 26 | 14,428,176 | 0 | 0 | PASS |
| 252.eon | 107,398 | 30 | 28,807,680 | 0 | 0 | PASS |
| 253.perlbmk | 85,333 | 31 | 22,918,608 | 0 | 2 | PASS |
| 254.gap | 70,946 | 26 | 19,121,944 | 0 | 0 | PASS |
| 255.vortex | 72,211 | 28 | 19,765,928 | 0 | 4 | PASS |
| 256.bzip2 | 37,502 | 22 | 10,173,312 | 0 | 0 | PASS |
| 300.twolf | 52,583 | 24 | 14,311,936 | 0 | 0 | PASS |

`program JIT` counts generated PCs inside the input ELF's executable sections.
`system JIT` counts generated PCs outside those sections. Perlbmk and vortex
execute guest VDSO/signal helper code around `0x5508004500`; that anonymous
mapping is not currently represented by LAT's file-backed AOT segment format.

Use full strict mode when no system TB is expected:

```sh
LATC_STRICT_AOT=1 LATC_STATS_OUT=stats.json ./program.la64 arguments...
```

For programs using guest VDSO/signal helper pages, require the main executable
to be fully AOT while retaining the explicit system JIT fallback:

```sh
LATC_STRICT_PROGRAM_AOT=1 LATC_STATS_OUT=stats.json ./program.la64 arguments...
```

The essential passing conditions are:

```text
pretranslated = 0
runtime_tb_gen_attempts = 0
runtime_program_tb_gen_attempts = 0
```

## Train validation and performance

The current performance metric and the 2.5 GHz 3A6000 baseline are recorded
in [PERFORMANCE_BASELINE.md](PERFORMANCE_BASELINE.md). Future optimization
results use `LA native runtime / translated runtime * 100%`; higher is better.
The older measurements retained below are historical and must not be used as
the current baseline.

`prepare-specint-train.py` runs the official train workload, builds an embedded
AOT image, then repeats strict execution until all observed main-program PCs
are present. `254.gap` needed two supplemental addresses. Profile addresses
outside the input ELF are rejected by default; this script opts in to ignoring
them for `perlbmk` and `vortex`, whose guest VDSO pages remain explicit system
fallbacks.

`compare-native-train.py` compares M4 standalone ELF, AOT v2 standalone ELF,
old LAT `AOT+TU`, and native LoongArch binaries on one pinned CPU. Pass the
AOT v2 executable, module, and runtime directories with `--aot-v2-dir`,
`--aot-v2-module-dir`, and `--aot-v2-runtime-dir`. The tool enables strict AOT
v2 execution and disables runtime pretranslation, so a missing or unusable
module fails instead of being misreported as AOT v2 performance. Use
`--lat-cache warm` for steady-state old AOT and `--lat-cache cold` to remove its
isolated cache before every measured run. The cold comparison includes old
LAT's runtime AOT construction, while M4 and AOT v2 translation costs were paid
when their ELFs were built.

On the 2.0 GHz 3A6000 host, three cold-cache rounds produced a geometric-mean
LATC/LAT speedup of **1.1473x**. All 36 measured LATC runs and all 36 LAT runs
passed SPEC validation. The same LATC binaries measured against warm LAT AOT
previously produced **0.9532x**, so LATC is not yet faster after LAT's cache is
already populated. Against native LoongArch in the cold-cache comparison,
LATC reached **0.6314x** geometric-mean performance.

Geometric mean speedup is **1.0195x**. All 60 measured bundle runs hit the
validated AOT cache. The main executable generated no runtime TB in any run.
The `perlbmk` and `vortex` system counts are translator-entry attempts per
strict validation run; they do not indicate main-program JIT. Across the 60
measured runs there were 50 system attempts and 30 installed system TBs.

These numbers compare two different AOT construction paths: latc generates an
AOT image from its CFG and observed missing targets, while the baseline uses
LAT's normal runtime-driven AOT cache. The result therefore measures the whole
output, not only bundle startup overhead. It is evidence for static main-program
execution, but not evidence that the output is independent of LAT.

Profile data is tied to the exact guest ELF hash and workload. Regenerate it
after changing the x86 binary, LAT code generator, optimization options, or
SPEC input size. A strict failure PC inside an executable section should be
added to the profile and the AOT output rebuilt; this was required twice for
254.gap.

## Native image prototype

The first stable native-image export was validated for `164.gzip` on the same
Loongnix 20 host. Two consecutive exports from the same runner, guest, and
profile produced the same SHA-256:

```text
image bytes: 6,587,520
guest bytes: 899,936
LoongArch code bytes: 2,623,952
TB records: 38,372
relocation records: 66,953
SHA-256: a613c175afa61a498c52dd327fe6b1429e335090c5389d3762366682c0edeb49
LAT build ID: lat-42c042301e107b34063773e118c825dd644d476c-x64-v1
```

`latc inspect-native` validates all file ranges, `(guest_pc, flags)` ordering,
TB code ranges, relocation slots, and runtime-symbol IDs. LAT's process-local
TU search data is removed because it contains host pointers.

This file is the intermediate input to `compile-native-elf.sh`, which applies
stable relocations and links the minimal runtime into an executable LoongArch
PIE. Precise recovery from an arbitrary signal PC is still pending because the
removed LAT search data has not yet been replaced by a stable PC map.

The LoongArch PIE embeds the image in `.latc.image`, maps gzip's x86 ELF range
at `0x400000-0x51c000`, applies relocations to a private RW mapping, changes it
to RX, prepares the x86 Linux initial stack and CPU state, then enters the
translated guest entry at `0x401cb0`.

Before attempting any SPEC program, the runtime executed a separate two-TB
static x86 fixture containing only `exit(42)`. LAT-generated LoongArch code ran
and reached the extracted x86 Linux syscall layer, which read x86 `RAX` and
`RDI` from the LAT environment and terminated with status 42. Native image
generation now accepts any validated static x86-64 ELF without `PT_INTERP`;
the runtime still requires the recorded LAT build ID to match.

### Direct static gzip execution

Validated on 2026-08-21 on the AOSC LoongArch 3A6000 host. The input was the
static x86-64 `gzip_base.Of.gcc830.dyn` executable and the official SPEC2000
test workload `input.compressed 2`.

```sh
tools/latc/scripts/compile-native-elf.sh \
  tools/latc/build/latc runner-build/latx-x86_64 \
  gzip_base.Of.gcc830.dyn gzip-static.la64
./gzip-static.la64 input.compressed 2 > output
cmp output input.compressed.out
```

The generated file is a 7,332,048-byte LoongArch PIE. It contains 38,672
translated TBs, 2,661,312 bytes of LoongArch code, and 83,164 relocations. Two
consecutive executions exited with status 0, produced no stderr, and matched
the 987-byte reference output byte for byte. The output SHA-256 was
`162841eda1a375560df7a597aa04638016d0429e27401a0106e9bbfc7cffff20`.

This path does not start `latx-x86_64` at runtime and has no runtime JIT. It
maps the embedded x86 load segments, enters the pre-generated LoongArch code,
and resolves indirect branches through the embedded TB table. The executable
still dynamically depends on the host LoongArch `libc.so.6` and loader; it is
not yet a fully static LoongArch ELF.

The minimal runtime now covers the Linux-user system calls exercised by all
twelve SPECint2000 train workloads, CPUID/cache discovery, and both direct and
indirect TB exits. Floating-point status conversion remains intentionally
conservative: the current no-op wrappers are valid for these integer workloads
but are not a complete x87 or non-default SSE rounding implementation.

### Direct static gzip train execution

The first unprofiled native image incorrectly appeared to finish the train
workload but produced different compressed sizes. Strict AOT exposed the real
problem: LAT requested a missing TB at `0x40bdcc`. The CFG block beginning at
`0x40b8c0` contains more than LAT's 255-instruction TB limit, and pretranslation
had not continued from the split point. Other missing targets included glibc
branches that deliberately enter after a `lock` prefix.

Pretranslation now continues every LAT TB that ends before its containing CFG
block, including max-length and internal translator splits, and compiles
executable targets from static CFG edges. For gzip this produces 38,685 TBs
from 38,672 CFG TBs: two length-limit continuations and eleven additional edge
targets. Native image export and validation reject any remaining direct target
without a TB.

Validated on 2026-08-21 on the AOSC LoongArch 3A6000 host with no workload
profile. Two consecutive `input.combined 32` executions exited with status 0,
produced no stderr, and matched the official 1,054-byte output. The SHA-256 was
`d716dd009b55c6c28d629b8bfabcda4bf6ce5cae9e7c77a27306f3d3193aa453`.
The matching strict AOT run reported zero runtime TB generation attempts.

```sh
make -C tools/latc test-spec-gzip-native \
  RUNNER=/path/to/latx-x86_64 SPEC_GZIP=/path/to/gzip.x86_64 \
  SPEC_GZIP_INPUT=/path/to/input.combined SPEC_GZIP_SIZE=32 \
  SPEC_GZIP_EXPECTED=/path/to/input.combined.out
```

### Direct SPECint2000 train execution

`run-specint-native.py` first compiles every selected static x86 executable,
places all generated LoongArch ELFs in a temporary SPEC binary directory, and
only then uses the official SPEC harness to run and validate each train
workload. It
restores `specbin/run` even when compilation or execution fails and writes a
manifest containing ELF hashes, inspection output, reported time, logs, and
the saved raw SPEC result.

On a LoongArch64 host, run one benchmark with:

```sh
make -C tools/latc test-specint-native \
  RUNNER=/path/to/latx-x86_64 \
  SPEC_ROOT=/path/to/spec2000-x64 SPEC_BENCHMARK=181.mcf
```

The native runner uses a 60-second timeout for each benchmark harness run by
default. This covers multi-command benchmarks such as perlbmk without allowing
a broken train run to wait indefinitely. Use `--timeout` when invoking
`run-specint-native.py` directly to change it.

Omit `SPEC_BENCHMARK` to compile and run all twelve SPECint2000 train
workloads. The generated executables still use the host LoongArch libc and
dynamic loader; the x86 program code and direct TB targets are fully generated
before execution, with no runtime LAT process or JIT fallback.

All twelve train workloads were regenerated and validated by the official SPEC
harness on the AOSC 3A6000 host on 2026-08-21. Every saved `.raw` result reports
`valid=1`. The harness allowed at most 60 seconds per benchmark; perlbmk, which
contains three commands, was the slowest at 44.11 seconds. Separate direct
execution checks limited every individual command to 30 seconds; the slowest
single command was perlbmk diffmail at 16.76 seconds. `175.vpr` passed the
official numeric tolerances (`costs.out` 5%, other outputs 1.5%). Every other
checked output matched the official output byte for byte.

| benchmark | official reported seconds | validation |
|---|---:|---|
| 164.gzip | 15.278481 | exact |
| 175.vpr | 11.676725 | SPEC tolerance |
| 176.gcc | 1.952317 | exact |
| 181.mcf | 5.156867 | exact |
| 186.crafty | 11.488029 | exact |
| 197.parser | 3.634140 | exact |
| 252.eon | 4.582264 | exact |
| 253.perlbmk | 44.114945 | exact |
| 254.gap | 3.712304 | exact |
| 255.vortex | 6.804299 | exact |
| 256.bzip2 | 12.111634 | exact |
| 300.twolf | 5.116180 | exact |

`176.gcc` required preserving switch-table targets that enter cold function
partitions and targets that begin inside an existing CFG block. The resolver
now validates cross-function cases against whole-program instruction
boundaries and known direct targets. `253.perlbmk` exposed repeated indirect
dispatch overhead; the native runtime now keeps a direct-mapped C lookup cache
while leaving LAT's generated FastTB cache in its conservative miss state.

The train result does not cover SPEC ref inputs. Asynchronous guest signal
frames, complete x87/SSE control-state conversion, and a fully static
LoongArch libc remain outside the current implementation.
