# AOT v2 M11：统一首次生成与增量追加

## 问题

当前运行时在退出阶段收集完整 TB 集合，`latcd` 把新集合与历史集合合并后重新编译
整个模块。第一次生成和后续补充虽然都使用 TB 集合，但后续每增加少量地址仍要重复
编译全部代码。长期运行进程也不能及时发布新增代码。重复执行和重复编译不能作为
100% AOT 覆盖率的证明。

## 需求

- 每个 TB 使用 `(source_sha256, guest_rva, semantic_flags)` 标识，不记录执行次数。
- 首次生成与增量追加调用同一个差集编译实现；缓存为空只是已发布集合为空。
- `latcd` 持久保存已接收、已发布和待编译集合。不同进程提交后按 source 取并集。
- 同一 source 只发布一个不可变 AOT 模块、一个完整 native image 和一个完整 TBSET。
- `flush` 等待调用前已接收的键全部发布，不等待进程退出，也不等待未来输入。
- 增量键先与当前模块的实际 TB 表比较；模块已经包含的键只更新 TBSET 和清单，
  不重复翻译或链接。其余键翻译后合入完整 native image，并链接一个替换模块。
- 不兼容旧的文本 TBSET、协议 v1 和旧格式 current 文件。

## 验收

- `flush` 成功后，屏障前每个键都有可加载的 AOT TB；缺少一个键即失败。
- Python、Git、SQLite 和 Redis 全依赖严格复跑的文件型 JIT TB 为零。
- 约 8 万 TB 的完整生成和完整合并均不超过 5 秒，10% 增量不超过 2 秒。
- 暖 AOT 相对已确认基线回退不超过 2%；启用收集后 JIT 相对关闭收集回退不超过
  1%；四个应用暖 AOT 均快于 JIT。
- 所有编译统计 `failed=0`，故障不会破坏最后一个可用清单。
