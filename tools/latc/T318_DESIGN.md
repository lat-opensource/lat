# T-318：三级 guest 地址表设计

## 格式

保留现有 256 个 `$fp` 负偏移槽。小模块继续使用两级表，每个槽指向 256 个 guest
地址，最多 65,536 个地址。超过该数量的模块设置
`LAT_AOT_MODULE_THREE_LEVEL_GUEST_SLOTS`：

1. 第一条 `ld.d` 从 `$fp` 负偏移槽读取根页指针。
2. 第二条 `ld.d` 从根页读取叶页指针。
3. 第三条 `ld.d` 从叶页读取 `guest_load_bias + guest_rva`。

每层 256 项，三级表最多表示 16,777,216 个地址。`LatAotGuestSlotV2` 不增大：
`fp_offset` 保存根页偏移，`reserved` 高 16 位保存中间页字节偏移，低 16 位保存叶页
字节偏移。三级表要求 guest 地址重定位预留 3 条指令。

## 运行时

每个模块实例分配一段指针和地址存储。前部是根页中的叶页指针，后部是实际 guest
地址页。模块切换只改 `$fp` 前的根指针，不复制整张地址表。旧的平面表和两级表按
原标志解释；同时设置两级和三级标志的模块拒绝加载。

## 编译器

打包器用哈希表为 guest RVA 分配稳定序号，避免大模块上线性查找。地址数超过
65,536 时选择三级编码。profile 的 65,536 条安全限制改用独立常量，避免与模块
内部 guest 地址数量再次混淆。

## 兼容性

描述符大小和 ABI version 不变，新格式通过 module flag 区分。构建身份变化会使旧
编译器、runner 和 runtime 组合在加载前被拒绝；同一新构建仍可读取旧两级格式。
