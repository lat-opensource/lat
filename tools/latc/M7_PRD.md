# AOT v2 M7：消除模块执行路径性能退化

## 背景

M6 在同一台 3A6000、同一 CPU 和相同 SPECint2000 train 输入上完成四模式各
5 轮对照。AOT v2 的几何平均效率只有 `42.47%`，M4 为 `67.12%`，旧 AOT
为 `64.78%`。AOT v2 相对 M4 的速度比为 `0.6328x`。动态 Bash 的暖缓存
运行也从冷运行 `8653 ms` 增加到 `10265 ms`。

## 目标

用可重复的计数器和 profile 证明性能损失发生在哪条执行路径，修复已证明的
主要原因，并恢复 AOT v2 在完整静态模块和部分动态模块上的实际收益。

## 必须完成的行为

- 固定 `3a6000-25g` 的 CPU 4，使用已提交的 M6 runner、输入摘要和产物作为
  修复前基线；不得把不同主机或不同输入的绝对时间混在一起。
- 建立 30 秒以内的差分测试，至少稳定复现 `176.gcc` 或 `252.eon` 上 AOT v2
  相对 M4 的退化，并保存 cycles、instructions、branches、branch-misses 和热点。
- 在修改前列出多个可证伪原因，逐项用 profile、计数器或单变量实验排除；不以
  未测量的直觉作为实现依据。
- 完整静态模块的 AOT 命中路径不得退化到逐 TB 的线性模块扫描、锁、重复校验、
  重复地址转换或不必要的 C 调用；实际原因以测量为准。
- 动态部分模块继续正确回退 JIT，不能通过关闭校验、信号安全或 M6 生命周期保护
  换取性能。
- 修复后重新执行四模式 5 轮对照。AOT v2 相对 M4 的 12 项几何平均速度比至少
  达到 `0.95x`，且 12/12 SPEC 输出校验通过。
- 真实动态 Bash 暖运行必须比 M6 的 `10265 ms` 有可重复改善；若仍不能快于冷
  运行，报告必须用模块覆盖率和 profile 说明剩余时间消耗。

## 范围

`tools/latc` 的 AOT v2 hot dispatch、模块/实例索引、地址转换、动态模块命中、
性能测试脚本和 M7 报告；在 `3a6000-25g` 上采集 LoongArch perf 数据。

## 不包含

- SPEC ref。
- 关闭 ELF 校验、W^X、并发生命周期保护或信号安全检查。
- 修改 `tools/latc` 之外的 LAT 核心功能，除非 profile 证明必须修改且另行记录范围。

## 完成标准

- 原始退化由快速测试稳定复现，修复后同一测试显著改善。
- profile 能解释修复前后的 cycles 差异，并删除所有临时诊断代码。
- 本机单测、ThreadSanitizer、远端 M1-M7 回归和 SPEC train 12/12 全部通过。
- M7 报告保留所有正式样本、输入摘要、perf 原始输出和未解决限制。
