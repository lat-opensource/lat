# T-318：Git 基本完全 AOT

## 问题

固定 Git 工作负载的暖运行只有 6,484 次 AOT lookup，却有 76,393 次 JIT
fallback。暖 AOT 比 JIT 快不能代替覆盖率验收；大多数已知代码仍由 JIT 翻译时，
AOT 不具备可用性。

原始 Git native image 有 178,711 个 TB 和 74,121 个不同 guest 地址。现有两级
guest 地址表只能表示 65,536 个地址。首批溢出会删除 TB，并沿直接跳转和顺序执行
依赖继续删除，最终模块只保留 16,398 个 TB。

## 需求和验收

- 固定 Git 工作负载的全部文件型 ELF 代码 AOT lookup 占比至少 99.9%；没有模块的
  ELF 产生的 lookup 也必须计入 JIT fallback，不能从分母中排除。
- JIT fallback 只允许逐项记录且不能静态编译的运行时代码；普通模块缺失不允许。
- `latcd` 必须 `requests=compiled`、`failed=0`。
- 暖运行不得提交新的编译请求，Git 输出和仓库校验必须正确。
- 同一 3A6000、同一构建上的暖 AOT 不得慢于 JIT。
- 旧的平面表和两级表模块继续通过格式与运行时测试。

## 范围

修改 AOT 模块 guest 地址寻址、模块验证、运行时表初始化和覆盖率测试。动态生成代码
及没有对应 ELF 的匿名代码不计入文件型模块覆盖率，但必须单独报告。
